🔋 What you get

One config-flow entry per wheel; every value lands as a proper HA entity with device classes, so dashboards, statistics and automations just work.

🔋

Real battery %

The wheel reports State of Charge directly — no voltage-curve guessing. Sticky across restarts, retained while the wheel sleeps.

⚡

Voltage, current, power

Pack voltage and signed current every 5 seconds, with power derived — negative while charging or regenerating.

🛞

Speed & odometer

Live speed and lifetime distance as a total_increasing sensor, ready for long-term statistics.

🔌

Charging that's honest

Charging is detected from current draw or a rising battery % at standstill — current alone fluctuates around zero on some chargers.

📶

Proxy-native

Connects through any ESPHome bluetooth proxy with active connections. The wheel reconnects automatically whenever it powers on in range.

🎚️

One-client switch

A Ninebot accepts a single BLE client. A per-wheel “maintain connection” switch releases it to the Ninebot app before a ride — automatable.

🧪 The protocol, decoded

Unlike Begode wheels (which free-stream), the Ninebot One answers polled register reads on the classic serial-over-BLE bridge (service FFE0, characteristic FFE1). Framing is shared in both directions:

55 AA <len> <src> <dst> <param> <payload…> <crcL> <crcH>

len = payload_len + 2          src App = 0x09 · dst Controller = 0x01
crc = (~sum(len … payload)) & 0xFFFF, little-endian

The integration asks for the serial number (0x10) and firmware (0x1A) once, then polls live data (0xB0) every 5 s. Older firmware answers with one 32-byte block; firmware 4.2.x answers in segmented register frames — both are parsed:

ResponseFieldsScale
0xB0 (32-byte block)battery, speed, distance, temp, voltage, currentlegacy firmware
0xB3battery %, speed% · /1000 km/h
0xB6total distanceu32 meters
0xB9temperature/10 °C
0xBCvoltage, current/100 V · /100 A (signed)

Scope: the original One E/E+ generation only — no frame encryption, no pairing dance. The Z / ES generations encrypt frames with a session key and need a different handshake (not supported here). Protocol knowledge ported from the WheelLog project (GPL-3.0), with credit and thanks.

🚀 Install

Plain custom component — no dependencies beyond HA's own Bluetooth stack.

# 1. copy the integration into your HA config
custom_components/ninebot_one/  →  /config/custom_components/ninebot_one/

# 2. restart Home Assistant

# 3. Settings → Devices & Services → Add integration → "Ninebot One EUC"
#    power the wheel on near a BLE proxy, pick it from the list, name it

You'll need at least one ESPHome bluetooth proxy with active: true in range of the wheel (or a local Bluetooth adapter). Mind the proxy's connection-slot budget if it also carries other devices — each proxy holds a few active links (configurable up to 5 comfortably).
